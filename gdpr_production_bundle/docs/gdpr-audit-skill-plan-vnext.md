## 0. Executive Decision

Keep three skills. Do not split by jurisdiction, role, maturity tier, or national law.

```text
intent / surface  → skill
stage             → profile
role              → profile
jurisdiction      → overlay
legal obligation  → control
evidence          → confidence
decision          → output
```

**In scope:** GDPR (EU) 2016/679; EU ePrivacy-style storage/access rules; UK PECR; Germany TDDDG; EDPB guidance; CJEU GDPR case law.

**Out of scope:** NIS2, AI Act, CRA, and non-privacy regimes unless a finding is independently grounded in GDPR or a direct privacy overlay.

## 2. Control Catalogue

**Source:** `gdpr-shared/controls/control-catalog.json`  
**Version target:** `2026.05-production-v1`  
**Current size:** 131 controls across 12 domains

### 2A. Active result schema

Canonical result values:

```text
pass | fail | unknown | not_applicable | needs_legal_review
```

`partial` is removed from the active schema. Any legacy `partial` result must be migrated to either `unknown` or `needs_legal_review`. If reintroduced later, it must have both producing control logic and explicit decision-layer gating.

### 2B. Enforcement rules

- No evidence → `unknown`, never `pass`.
- `non_enforceable` → never automated `pass` or `fail`.
- `applies_if` must run before evaluation.
- No global “GDPR compliant” output.
- Legal-review routing must be explicit; `needs_legal_review` alone is not enough for A6.

### 2C. Catalogue invariants

`validate_catalog()` in `control_engine_guard.py` blocks builds on:

| Rule | Condition | Action |
|---|---|---|
| INVAR-01 | `included == true` and `priority == "out_of_scope"` | `CatalogError` |
| INVAR-02 | `included == false` and `priority != "out_of_scope"` | `CatalogError` |
| INVAR-03 | enterprise included count != 131 | `CatalogError` |
| INVAR-04 | early included count > 30 | `CatalogError` |
| INVAR-05 | growth included count outside 60–90 | Warning requiring explicit acceptance |

The schema is computed externally from per-control `stage_profile` data. It is not duplicated as manual prose.

## 6. Output Contract

Each run may produce multiple artefacts.

| Artefact | Audience | Source |
|---|---|---|
| Control findings | engineer / DPO | control engine |
| Remediation report | product / engineering | decision layer |
| Legal review packet A6 | counsel / DPO | A6 routing filter |
| Checklist | mixed | guide |

### A6 legal review packet

```json
{
  "control_id": "",
  "facts": "",
  "legal_sources": [],
  "question": "",
  "evidence": []
}
```

A6 is factual only: no remediation, no automated legal conclusion, no technical ticketing language.

### A6 routing filter

Route to A6 only when all are true:

```text
needs_legal_review == true
AND decision_flags.routes_to_legal_review_if_triggered == true
AND enforceability != "technical"
AND output_routing.legal_review_packet != "off"
```

Technical controls may surface DPO risk hints but must not auto-route to counsel unless explicitly flagged by catalogue metadata.

## 7. Decision Layer

```text
control_engine → decision_layer → outputs
```

### Responsibilities

- summary gating
- severity aggregation
- legal routing
- role filtering
- staleness effects

### Coverage formula

```text
coverage = assessed_controls / applicable_controls
```

Definitions:

- `applicable_controls`: controls whose `applies_if` evaluates true and are active for the selected stage.
- `assessed_controls`: applicable controls producing `pass`, `fail`, `unknown`, or `needs_legal_review`.
- `not_applicable` controls are excluded from the denominator.
- `unknown` counts as assessed but may block clean summaries through `decision_flags`.

### Summary gating

Clean or reassuring summaries are blocked unless all are true:

```json
{
  "coverage >= threshold": true,
  "critical_failures == 0": true,
  "high_risk_unknown == 0": true,
  "anti_overclaiming_guard_passed": true
}
```

Else output:

```text
Assessment incomplete — insufficient evidence.
```

### Mandatory evaluation order

1. Compute `high_risk_unknown` across all active applicable controls where `counts_as_high_risk_unknown == true`.
2. Compute `critical_failures`.
3. Evaluate SCOPE-008 anti-overclaiming guard.
4. Evaluate coverage threshold.
5. Generate summaries only if all gates pass.

### Severity aggregation

```json
{
  "critical >= 1": "high_risk",
  "high >= 3": "high_risk",
  "medium >= 5": "moderate_risk",
  "else": "low_risk"
}
```

Severity aggregation drives remediation prioritisation only. It does not create legal conclusions.

### Staleness rule

If a control is stale and `decision_flags.requires_human_review_if_stale == true`, the result becomes `needs_legal_review` unless the control is inactive for the selected stage.

## 9. Auditor Operational Safety

The `auditor_operational_safety` domain is evaluated as a shared preflight before skill-specific phases.

### Internal blocking checks

- credential handling
- PII-safe logging
- destructive-action safeguards
- raw evidence retention limits

### External disclosures

- production data used
- elevated access used
- evidence contains personal data

Internal safety controls do not create user-facing compliance findings unless they affect audit risk or report shareability.

## 10. Evidence Model

| Tier | Source | Confidence |
|---|---|---|
| Tier 1 | scanner, crawler, repo, app flow, cloud/IaC | `confirmed` or `likely` |
| Tier 2 | questionnaire | `self_reported` |
| Tier 3 | parsed document | `confirmed_from_document` |
| Human | reviewer | `reviewed` |

Stage evidence policy must be enforced by `control_engine_guard.get_evidence_policy(control, stage)` only.

Enterprise rule: Tier 2 alone cannot produce `pass` for high or critical controls unless the catalogue explicitly allows it and the output is visibly labelled `self_reported`.

## 12. Shared Engine Ownership

Canonical location: `gdpr-shared/scripts/`

**Role:** catalog-validation tooling only. Skills evaluate controls conversationally — the Python engine is not invoked at session runtime.

Modules:

- `control_engine.py` — reference evaluation logic (not called by skills at runtime)
- `control_engine_guard.py` — catalog invariant enforcement (INVAR-01–05); `validate_stage_counts()` computes stage counts from per-control `stage_profile` metadata
- `jurisdiction_router.py` — overlay resolver
- `decision_layer.py` — coverage formula, severity aggregation, `can_emit_summary()` gate, `route_to_a6()` with all four routing conditions

No duplicated skill-local copies are allowed.

### Guard rule

`stage_evidence_policy[stage]` must not be evaluated unless `stage_profile[stage].included == true`.

All logic must call:

```text
control_engine_guard.get_evidence_policy(control, stage)
```

A `None` return produces `not_applicable` with no further processing.

## 16. Success Criteria

- Every evaluated result maps to `control_id`.
- No missing evidence becomes `pass`.
- No non-enforceable control produces automated `pass` or `fail`.
- No blanket compliance claim is emitted.
- A6 contains only legal-reviewable items.
- Technical-only findings do not auto-route to counsel.
- Coverage uses the formula in §7.
- Severity aggregation is deterministic.
- Stale high-sensitivity controls trigger human review where flagged.
- Stage evidence policy is never evaluated for inactive controls.
- Guide output never emits audit findings, severity, or coverage.
